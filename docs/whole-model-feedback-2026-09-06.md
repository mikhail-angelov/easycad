# Полная геометрия в обратной связи — 2026-09-06

## Задача и границы

Следующее небольшое улучшение после `67a92e3`: исправить общий контекст
геометрии для разных типов деталей, без доработки рецепта резьбы.
Основание — пользовательский запрос улучшать приложение в целом, а не только
болты, и существующий контракт Geometry Info в SPEC11 / SPEC20.

Требования:

- Размеры, bounding box и топология описывают весь экспортируемый результат.
- Многотельные модели допустимы: корпус и отдельная крышка — не ошибка.
- Измерения доходят до следующего запроса генератору; редактор по-прежнему
  получает исходный код без служебного блока.
- Одиночные детали, STL/STEP и изоляция CadQuery продолжают работать.
- Нет новых LLM-вызовов, зависимостей, правил генерации или автоматических отказов.

## Причина

`cq.exporters.export` в установленном CadQuery 2.8.0 экспортирует `Shape`
напрямую, а все элементы `Workplane`/iterable объединяет в compound.
Существующий `get_geometry_info` измерял только `result.val()` — первый
элемент стека. При нескольких отдельных телах данные противоречили STL.
Для напрямую возвращённого `Shape`, который экспорт уже поддерживал,
измерения вообще заменялись на `could not extract`.

Воспроизведение через настоящий subprocess: два прямоугольных тела занимают
`X=0..30, Y=0..20, Z=0..40`. STL содержит оба, а обратная связь до исправления
сообщала `10×20×30 мм, 1 solid`. Две регрессии до изменения упали именно
на измерениях, не на экспорте.

## Изменение

В `app/cq_worker.py` результат один раз приводится к `Shape` — напрямую либо
через `cq.Compound.makeCompound`. Экспорт и измерение получают один и тот же
объект. Тела не сливаются boolean union, не перемещаются и не обрезаются.
Общий execution core используется локальным subprocess и hosted worker;
для hosted-режима потребуется обычная пересборка образа, деплой здесь не выполнен.

## Проверка

Регрессии используют `execute()` с реальным CadQuery, не подменяют геометрию.
В тесте двух тел дополнительно независимо читаются вершины бинарного STL.

| Случай | Ожидаемые размеры, мм | Тел |
|---|---|---|
| Два блока: Workplane и raw compound | 30×20×40 | 2 |
| Пластина с четырьмя отверстиями | 80×50×4 | 1 |
| Две разнесённые шайбы | 50×20×13 | 2 |
| Полый корпус и отдельная крышка | 100×30×20 | 2 |
| Одиночный raw solid | 12×15×18 | 1 |

API-регрессия сохраняет корпус с крышкой, затем выполняет `/api/chat`.
Подменён только внешний completion: проверяются реальные сообщения генератору
с полной измеренной геометрией и отсутствие служебных комментариев в коде UI.
Она проверяет доставку контекста, не качество ответа настоящего LLM.

Для корпуса используется прямоугольный карман `cutBlind(-18)`. Первоначальный
fixture через `shell(-2)` в этом окружении дал другой тип топологии при
итерации Workplane: объект-обёртка `Compound` содержал `Solid`, но итератор
раскрыл его до `Shell`. Сам exporter тоже использует этот итератор; поэтому
корпус с крышкой экспортировался как shell + solid, и правильный счётчик
показывал только один solid. Карман проверен отдельно: экспортируемый compound
содержит solid. Этот отдельный эффект CadQuery здесь не исправлялся.

Команды:

```sh
CADQUERY_WORKER_TIMEOUT_SECONDS=120 XDG_CACHE_HOME=$PWD/.cache PYTHONDONTWRITEBYTECODE=1 \
  .venv-poc/bin/python -m pytest tests/test_cadquery_exec.py tests/test_spec20.py -q
CADQUERY_WORKER_TIMEOUT_SECONDS=120 XDG_CACHE_HOME=$PWD/.cache PYTHONDONTWRITEBYTECODE=1 \
  .venv-poc/bin/python -m pytest -q
git diff --check
```

Результат: целевые проверки — **18 passed**; полный набор — **340 passed,
24 skipped**, 180.33 с. Есть одно предупреждение устаревшего API Starlette/AnyIO.
Независимое ревью по стандартам и соответствию задаче — без замечаний.
`git diff --check` проходит. Изменение оставлено незакоммиченным.

## Что результат не доказывает

Это детерминированное исправление неверных измерений, не новый semantic repair.
Габариты и число тел не доказывают, что отверстие находится на нужной стороне,
толщина верна, резьба подходит или деталь соответствует тексту. Vision не добавлялся.
Платный A/B генерации для этой задачи не запускался; прирост продуктовой доли
правильных моделей и ускорение генерации не заявляются.
