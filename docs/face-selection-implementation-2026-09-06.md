# Выбор плоской поверхности — реализация MVP

Дата: 6 сентября 2026. Реализация после исследования
`research-face-targeting-2026-09-06.md`.

## Что появилось

В панели модели есть «Выбрать поверхность». В режиме выбора отображаются
буквенные метки видимых плоских граней, пригодных для операции в центре.
Клик выделяет грань, оставляет её подсветку и метку (например, A), а чат
показывает прикреплённую цель «Целевая поверхность A». При отправке запроса
сервер передаёт генератору только серверно проверенные центр и нормаль грани.

STL остаётся форматом просмотра при недоступной карте граней и форматом
скачивания. STEP-скачивание не менялось. Для выбора worker строит отдельную
отображаемую сетку, разбитую по CAD-граням; он не сопоставляет грань с индексом
отдельно экспортированного STL.

## Контракт безопасности и актуальности

- Ссылка состоит из случайного `revision` снимка и локального `face_id`.
- Сервер принимает её только для текущего шага той же сессии и только если код
  редактора совпадает с кодом, из которого построен снимок.
- Успешная генерация, ручной запуск, возврат к шагу, импорт проекта и предпросмотр
  варианта очищают выбор в UI. У новой успешной модели новая ревизия.
- Устаревшая ссылка получает `409 stale_face_selection` до запроса к провайдеру.
- Неизвестная грань, неполная ссылка и непригодная поверхность получают `422`.
- Первая версия принимает только плоскую грань, чей центр принадлежит обрезанной
  поверхности. Кривые грани и плоскости с отверстием не выдаются за безопасный
  «центр» операции.

В LLM попадает контекст вида `TARGET SURFACE (server-verified)` с буквой,
центром в миллиметрах и наружной нормалью. Браузерные координаты и нормаль не
являются источником истины. Это сокращает неоднозначность места операции, но
не гарантирует, что свободно сгенерированный код уже сделал корректную
гравировку: размер текста, глубина и проверка результата остаются следующей
задачей.

## Границы MVP

Карта создаётся только если модель имеет до 500 граней и до 50 000 индексов
треугольников. При превышении лимита обычное построение и STL работают, но
режим выбора не показывается. Метки отображаются только во время выбора и не
более чем для 30 плоских граней — так сложная деталь не превращается в облако
букв. Рёбра, вершины, множество граней и обтекание текста вокруг цилиндра не
входят в этот срез.

## Проверка

`tests/test_cadquery_exec.py` строит реальные BRep и проверяет карту шести
граней коробки; отдельный тест кольцевой поверхности подтверждает, что её
центр находится в отверстии и не принимается как целевой. `tests/test_face_selection.py`
проверяет API: доставка проверенной грани в генератор, устаревшая ревизия,
несовпадающий код редактора и недопустимое кольцо. Frontend build проверяет
типы и сборку viewer; frontend unit-тесты сохраняют контракт интерактивных
элементов.

Проверки завершены: целевые backend/API-тесты — 28 passed; полный Python-набор
— **347 passed, 24 skipped** за 187.07 с. Frontend: `npm run build` и `npm test`
прошли (23 теста). Есть известное предупреждение устаревшего API Starlette/AnyIO
и предупреждение Vite о крупном уже существующем viewer chunk. Двухосевое review
не оставило открытых замечаний: метки скрытых граней исправлены через depth test,
а stateless `/api/execute` больше не выдаёт карту без ревизии. Это не является
измерением роста качества генерации или готовностью к деплою.
